# ログインなしで見られるリンクを共有する

リンク共有を使うと、URL を知っている人が Artifact Share にログインせずにファイルを閲覧できます。リンクには終了日を設定でき、ワークスペースの方針で許されていれば無期限にもできます。

## Web では「共有範囲」からリンクと期限を設定する

1. ファイルの「共有範囲」を開きます。
2. 「リンクを知っている全員」を選びます。
3. 「リンクの期限」で終了日を選びます。「無期限」が表示されていれば、そちらも選べます。
4. 設定を変えたら「保存」を選びます。保存後はダイアログに出る `https://<id>.artifactshare.link/` をコピーするか、画面上部の「共有リンクをコピー」を使います。「受け取り側の表示を開く」を使うと、ログインしていない人にどう見えるかを送る前に確かめられます。

受け取り用の URL には、ファイルごとに専用のサブドメインを使います。所有者がログインして管理するときは、これまでどおり `https://artifactshare.com/a/<id>` を開きます。

受け取り側の画面では、作成者名の横に小さな ⓘ が付きます。ここを開くと、Artifact Share の利用者が共有したページであることと「通報」のメニューが表示されます。作成して間もないアカウントが共有したページから外部リンクを開こうとしたときは、移動先を確かめる確認画面が出ます（修飾キーを押しながら新しいタブで開いたときは表示されません）。

選べる終了日は、ワークスペースに設定された最長期限までです。新しいリンクには、ワークスペースの既定期限があらかじめ入ります。新しく作ったワークスペースの初期設定は「既定 30 日・最長期限なし」です。既存のワークスペースでは保存済みの設定がそのまま使われ、プランを変えても書き換わりません。期限の設定はオーナーが Web の設定画面から変えられ、Team プランでは管理者も変更できます。

## 期限が切れると、URL だけでは閲覧できなくなる

終了日を過ぎると、URL を知っているだけの人はファイルを開けなくなります。ファイルの投稿者や管理者、個別に共有された人など、別の閲覧権限を持つ人はそのまま閲覧できます。

投稿者や管理者の画面には、期限切れの状態と現在の期限が表示されます。もう一度リンクで共有したいときは、現在のポリシーの範囲内で新しい終了日か無期限を選び直して再公開します。

Team プランの管理者がワークスペース全体でリンク共有を無効にした場合も、既存のリンクは URL だけでは見られなくなります。あとから再び有効にしても、すでに期限が切れているリンクが自動で再公開されることはありません。

## プランごとに使える機能と管理範囲が異なる

- **Free**: ファイルごとにリンク共有を使えます。期限の設定項目は Plus と同じです。新しいワークスペースには最長期限がないため、設定を変えずに無期限も選べます。既存のワークスペースでは保存済みの最長期限が使われ、オーナーが Web の設定画面から変更できます。なお、社外メンバーからの投稿は Free では使えません。
- **Plus**: ファイルごとにリンク共有を使えます。オーナーは、新しいリンクに自動で入る既定期限と、利用者が選べる最長期限を設定できます。社外メンバーからの投稿も使えます。リンク共有や社外メンバーからの投稿をワークスペース全体で止める設定はありません。
- **Team**: オーナーと管理者が期限ポリシーを設定できます。リンク共有と社外メンバーからの投稿は、それぞれワークスペース全体でオン・オフを切り替えられます。新しいワークスペースの初期設定では、リンク共有はオフ、社外メンバーからの投稿はオンになっています。

既定期限と最長期限は 1〜365 日のあいだで指定できます。既定期限は「無期限」、最長期限は「制限しない」にすることもできます。ただし、既定期限を無期限にできるのは、最長期限が「制限しない」のときだけです。最長期限を短くすると、無期限のリンクも含めて、新しい上限より先に切れる既存のリンクもまとめて短縮されます。これらの方針は Web の設定画面から変更します。

## 新しい Free ワークスペースの上限

作成から間もない Free ワークスペースには、リンク公開の上限がかかることがあります。初期設定では、作成から 14 日未満のワークスペースでリンクを公開するたびに直近 24 時間の件数を数え、対象ファイルが 20 件に達していると、それ以上の公開を拒否します。

件数は 1 ファイルにつき 1 件として数えます。基準になる時刻は「リンク共有へ切り替えた時点」と「リンク共有の状態で新規作成した時点」のうち新しいほうです。すでにリンク共有になっているファイルを編集しても件数は増えません。なお、非公開に戻したり、リンク共有を止めたり、ファイルを削除したりしても、公開履歴はその公開から 24 時間経つまで残るため、空き枠はすぐには戻りません。

上限に達すると、次のリンク公開は拒否されます。事前の確認で空きがあっても、別の公開が同時に走ると最終判定で拒否されることがあります。すでに公開済みのリンクはそのまま使え、直近 24 時間の件数が上限を下回れば再び公開できるようになります。Web API・MCP・CLI の応答には、最も古い集計対象から計算した待ち時間が返るため、その時間を待ってから再試行してください。個別共有はこの上限の影響を受けず、いつでも使えます。Plus と Team にはこの上限自体がありません。

上限に達したときや、ほかの自動検知が働いたときには、自動レビューが始まることがあります。ただし、公開の拒否はレビューの有無や結果にかかわらず適用され、レビューを通っても上限が解除されることはありません。通報は自動レビューとは別に運営者へ届きます。どちらの経路でも、ファイルや既存のリンクが自動で書き換えられることはありません。

## レビュー後の一時停止と異議申立て

運営者は、レビューや通報の内容を確認したうえで、ファイルのリンク共有を手動で一時停止することがあります。停止中は URL だけを持つ人の閲覧を止めますが、所有者と個別に共有された人はそのまま開けます。

停止したときは所有者へ理由をメールで知らせ、ログイン後のファイル画面にも停止状態を表示します。所有者はその画面から異議を送れます。運営者がリンク共有を再開したときも、所有者へメールで知らせます。自動レビューだけでリンクが停止することはありません。

## MCP と CLI での期限指定とエラー対応

MCP の `share_artifact` と `edit_artifact` では、`link_expires_at` に RFC 3339 形式の UTC 日時を渡すと有限の期限になり、`null` を明示すると無期限になります。作成時に省略するとワークスペースの既定期限が入り、編集時に省略すると現在の期限がそのまま保たれます。

CLI では、有限の期限に `--link-expires-at <RFC3339 UTC>`、無期限に `--no-link-expiry` を使います。この 2 つは同時に指定できません。

MCP と CLI の作成・編集・取得の結果には、有限期限の UTC 日時か、無期限を表す `null` が `link_expires_at` として返ります。失敗した理由はエラーコードで区別でき、ワークスペース設定でリンク共有が止まっている場合、日時の形式が不正または最長期限を超えている場合、新しい Free ワークスペースの 24 時間上限に達した場合で、それぞれ別のコードが返ります。

公開上限のエラーコードは、MCP と Web API が `link-publish-rate-limited`、CLI が `link_publish_rate_limited` です。MCP では返された待ち時間を守り、エラーメッセージとヒントの案内に従ってください。CLI では `error.recovery` が `retry_later` になるため、`error.message` と `error.hint` で時期を確かめてから再試行します。同じリンク公開をすぐ繰り返さず、示された待ち時間か集計期間が過ぎるまで待ってください。
