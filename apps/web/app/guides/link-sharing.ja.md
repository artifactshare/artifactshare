# ログインなしで見られるリンクを共有する

リンク共有を使うと、URLを知っている人がArtifact Shareへログインせずにファイルを閲覧できます。リンクには終了日を設定できます。ワークスペースのポリシーで許可されている場合は、無期限にもできます。

## Webでは「共有範囲」からリンクと期限を設定する

1. ファイルの「共有範囲」を開きます。
2. 「リンクを知っている全員」を選びます。
3. 「リンクの期限」で終了日を選びます。「無期限」が表示されている場合は、選択できます。
4. 設定を変更した場合は「保存」を選びます。リンク共有の設定後は、ダイアログに表示された`https://<id>.artifactshare.link/`をコピーするか、ファイル画面のヘッダーにある「共有リンクをコピー」を使います。「受け取り側の表示を開く」で、ログインしていない人の画面を確認してから送ることもできます。

受け取り用のURLでは、ファイルごとに専用のサブドメインを使います。所有者がログインして管理するときは、引き続き`https://artifactshare.com/a/<id>`を開きます。

受け取り側の画面には、作成者名の横に小さな ⓘ があります。開くと、Artifact Shareの利用者が共有したページであることの説明と「通報」を表示します。新しいアカウントが共有した内容からArtifact Share外のリンクをクリックした場合は、移動先を示す確認画面で続行またはキャンセルを選びます（修飾キー付きで新しいタブに開く操作では表示されません）。

選べる終了日は、ワークスペースに設定された最長期限までです。新しいリンクにはワークスペースの既定期限があらかじめ入ります。新しいワークスペースは既定30日、最長期限なしで始まります。既存のワークスペースでは、現在保存されている期限設定を使い、プランを変えても書き換えません。オーナーはWebの設定画面から変更でき、Teamでは管理者も変更できます。

## 期限が切れると、URLだけでは閲覧できなくなる

終了日を過ぎると、URLを知っているだけの人はファイルを閲覧できません。ファイルの投稿者、管理者、個別に共有された人など、別の閲覧権限を持つ人は引き続きアクセスできます。

投稿者または管理者には期限切れの状態と現在の期限が表示されます。もう一度リンクで共有する場合は、現在のポリシー内で新しい終了日または無期限を選んで再公開します。

Teamプランの管理者がワークスペース全体のリンク共有を無効にした場合も、URLだけによる既存リンクの閲覧は停止します。再び有効にしても、すでに期限が切れたリンクは自動では再公開されません。

## プランごとに利用可否と管理範囲が異なる

- Freeでも、ファイルごとにリンク共有を選べます。期限の設定項目はPlusと同じです。新しいワークスペースには最長期限がないため、設定を変えずに無期限も選べます。既存のワークスペースでは現在保存されている最長期限を使い、オーナーがWebの設定画面から変更できます。社外メンバーからの投稿はFreeでは利用できません。
- Plusプランでは、ファイルごとにリンク共有を選べます。オーナーは、新しいリンクに入る既定期限と、利用者が選べる最長期限を設定できます。社外メンバーからの投稿も利用できます。リンク共有や社外メンバーからの投稿をワークスペース全体で無効にする設定はありません。
- Teamプランでは、オーナーと管理者が期限ポリシーを設定できます。リンク共有と社外メンバーからの投稿は、それぞれワークスペース全体で有効または無効にできます。新しいワークスペースでは、リンク共有は無効、社外メンバーからの投稿は有効です。

既定期限と最長期限には1〜365日を指定できます。既定期限は「無期限」、最長期限は「制限しない」にすることもできます。既定期限を無期限にできるのは、最長期限が「制限しない」の場合だけです。最長期限を短くすると、無期限を含め、それより後に切れる既存リンクの期限も短縮されます。管理ポリシーの変更はWebの設定画面から行います。

## 新しいFreeワークスペースの上限

新しいFreeワークスペースには、公開上限が適用されることがあります。
初期設定では、作成から14日未満のワークスペースを対象に、公開前の確認で直近24時間に20件のファイルを集計すると、その公開を拒否します。
各ファイルは最大1件として、直近の該当時点を使います。
リンク共有へ変更した時点が該当し、リンク共有の状態で作成した場合は、作成時点も候補になります。
すでにリンク共有しているファイルの編集は件数に加えません。
ファイルを非公開に戻したり、リンク共有を停止したり、削除したりしても、公開履歴はその公開から24時間の集計期間が終わるまで残ります。そのため、これらの操作で空き枠は戻りません。

集計件数が上限に達すると、次のリンク公開は拒否されます。
公開前の確認で空きがあっても、同時に行われた公開との最終判定で拒否されることがあります。
既存のリンクはそのまま使えます。
集計件数が上限を下回ると、再び公開できます。
Web API、MCP、CLIの応答には、最も古い集計対象を基準にした再試行までの待機時間が示されます。その時間を守って再試行してください。個別共有はいつでも使えます。
PlusとTeamにはこの上限はありません。

上限に達したときは自動レビューが始まることがあります。
公開の拒否は、レビューが開始または完了したかどうかにかかわらず適用され、レビュー結果で上限が解除されることもありません。
別の自動シグナルでもレビューが始まることがあります。
通報はこれとは別に運営者へ通知され、どちらの経路でもファイルや既存のリンクが自動的に変更されることはありません。

## レビュー後の一時停止と異議申立て

運営者は、レビューや通報の結果に応じて、ファイルのリンク共有を手動で一時停止できます。
停止中はURLだけを持つ人のアクセスを拒否しますが、所有者と個別に共有された人は引き続き開けます。
所有者には理由をメールで知らせ、ログイン後のファイルページに停止状態を表示します。
所有者はそのページから異議を送れます。
運営者がリンク共有を再開すると、所有者にもメールで知らせます。
自動レビューだけでリンクが停止することはありません。

## MCPとCLIでは有限期限、無期限、省略を使い分ける

MCPの`share_artifact`と`edit_artifact`では、`link_expires_at`にRFC 3339形式のUTC日時を指定すると有限期限、`null`を明示すると無期限になります。作成時に省略した場合はワークスペースの既定期限が使われ、編集時に省略した場合は現在の期限が維持されます。

CLIでは、有限期限に`--link-expires-at <RFC3339 UTC>`、無期限に`--no-link-expiry`を使います。この2つは同時に指定できません。

MCPとCLIの作成・編集・取得結果には、有限期限のUTC日時または無期限を表す`null`として`link_expires_at`が含まれます。失敗時は、ワークスペース設定による無効化、日時の形式不正または最長期限超過、新しいFreeワークスペースが直近24時間の公開上限に達したことを、それぞれ異なるエラーコードで確認できます。公開上限のコードは、MCPとWeb APIでは`link-publish-rate-limited`、CLIでは`link_publish_rate_limited`です。MCPでは返された待機時間を守り、エラーメッセージとヒントの指示に従います。CLIの`error.recovery`は`retry_later`を示すため、再試行の時期は`error.message`と`error.hint`で確認し、返された待機時間を守ってください。同じリンク公開をすぐに再試行せず、示された待機時間または集計期間の後に再試行してください。
