# Contributing to Artifact Share

Artifact Share currently accepts proposals, not code contributions. You do not need to implement or maintain a change you propose; maintainers handle the issue, specification, implementation, verification, and release after accepting a proposal.

## Submit a proposal-only pull request

1. Add one human-written `.md` or `.txt` file under `proposals/`.
2. Describe your situation, the problem, the change you expect, and any context needed to decide. A small, safe reproduction is welcome.
3. Open a pull request that changes only that proposal file. Do not include code, configuration, generated files, or edits to existing documentation.

You do not need generative AI to make the proposal longer. Direct language and concrete observations are more useful. See [the proposal guide](proposals/README.md) for the content and safety requirements.

Maintainers may edit relative links in a proposal before merge so they resolve from its final repository path. Do not use issue or pull-request shorthand such as `#123`; describe the relevant fact in the proposal instead.

## Keep proposals safe to publish

Proposals are public. Do not include customer or personal names, personal information, real email addresses, private repository or Artifact Share URLs, external issue or pull-request URLs, credentials, or production data. Use fictional values and generalized repository fixtures in reproductions.

Do not report vulnerabilities in a proposal or public issue. Follow [the security policy](SECURITY.md).

## Licensing

You retain copyright in your proposal and provide the license described in [the repository license](LICENSE). Artifact Share is source-available and is not OSI-approved open source. Ordinary code pull requests are not accepted at this time; terms for future code contributions will be defined separately after legal review.
