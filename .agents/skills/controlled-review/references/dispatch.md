# 呼び出し元がレビュー役を制御する

同じ依頼文をCodexとClaude Codeで使う。プロバイダー固有の組み込みレビュー機能や、親のsystem promptへの追記だけに依存しない。依頼文の生成は `scripts/render_prompt.py`、起動・待機・採否は統括役が担当する。

## Codex

ネイティブのサブエージェント機能がある場合、独立したコンテキストへ生成済みの依頼文を全文渡す。利用環境のAPIに従ってモデルとeffortを指定する。全履歴forkではモデルを指定できない環境なら、必要な情報を依頼文に含めて履歴なしで起動する。親の履歴にしか存在しない制約を残さない。

すべての依頼の結果を統括役が待つ。`wait_agent` の時間指定など、セッション固有の実行規約を守る。CLIで起動する場合も通常の実行モードへ全文を渡し、`codex review` に差し替えない。

## Claude Code

スキルは親のコンテキストで使う。生成済みの依頼文を `Agent.prompt` に全文渡し、指定されたモデル・effortを使う。Agent APIで必要なeffortを指定できない場合は、設定を扱えるCLIなどの経路を使うか、要求どおりに指定できないことを統括へ返す。無言で別設定へ置き換えない。

結果が同じ統括へ戻る経路を使う。CLIでは `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` がすべての子を前景実行にする設定。既存セッションで前景実行を指定できない場合は、完了通知の受け取り先を確認し、子の結果を待てることを確かめる。`/code-review` を内部で呼ぶことや、スキルに `context: fork` を追加することはしない。

通常の `claude -p` へ文字列を渡す場合、標準入力を閉じるか、標準入力そのものを依頼文の唯一の入力元にする。起動スクリプトの標準入力が `-p` の文字列へ追加されないようにする。ファイル本文をシェルのコマンド置換へ埋め込まず、プロセスAPIの文字列引数として渡す。

## 制御の確認

スキルはサンドボックスではない。利用可能なら、子のツールから再委譲・編集・公開を外すなど、指定された許可範囲を実行環境でも制限する。使えない機能を制限済みとは書かない。子が再委譲や範囲外の実行を試みた場合は、その依頼の結果を無条件に完了扱いにせず、統括が逸脱を確認する。

各呼び出しの依頼本文、呼び出しID、要求した設定、観測できた設定、結果を残す。子のローカル候補IDは呼び出しIDとの組で扱う。標準の実行記録で足りる場合は新しい収集機構を作らない。記録から子の初回依頼文を読める場合は、渡した本文と照合できる。システム指示・ツール定義を含む全入力を観測できたとは限らない。

サブエージェント機能がない場合、統括自身による単独レビューは可能だが、独立した探索・検証を行ったとは扱わない。指定モデルや実行上限が実現できない場合も、未完了の範囲を返す。
