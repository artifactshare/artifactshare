# 全レビュー役へ渡す作業条件

内容を指定済みの依頼や作業記録から埋める。これは人が読めるひな形であり、固定スキーマや新しい状態管理ではない。不要な項目は「該当なし」、不明は「未確認」と区別する。

```markdown
# 今回のレビュー条件

## 対象
repository: /absolute/path
base: 固定SHA
head: 固定SHA
paths: 対象パス、または全差分
diff: 固定した差分の絶対パス、または固定したbase/head SHAを指定するGit操作
source access: base/head双方の対象コードを読める固定スナップショット、または固定SHAを読み取れるGitリポジトリ
snapshot: 明示された未コミット変更がある場合の、固定内容と差分の保存先

## 目的と受け入れ基準
利用者に必要な変更と、満たせば完了と判断できる条件。

## 対象外・許容したトレードオフ
今回求めないことと、その理由。

## 適用規約
該当する規約と必要な本文、その版を特定できる情報。単なるファイル名だけでなく、子が読める固定した本文を渡す。リポジトリ内の規約を参照させる場合は対象SHAの版を使い、作業ツリーなど別の版と衝突したら黙って選ばず報告させる。上位の指示は引き続き適用する。

## 既存指摘の処分
ID / fixed・non-actionableなどの処分 / 理由 / 再検討が必要になる新しい根拠
初回なら「既存指摘なし」。

## 検証状況
実行済みのコマンド・対象・結果。未確認のこと。

## 実行条件
実行する観点と担当モデル・effort、並列数、候補数、追加呼び出し・再試行・時間の上限。既定を使う項目も、解決後の実値を書く。
子に許可する検証。指定がなければ読み取りのみで、テスト実行や再委譲は不可。
固定SHAやスナップショットの内容を読むGit操作は読み取りであり、対象コードの実行やテストとは区別する。
不足した検証は実行せず統括へ返す。
```

子へ渡す前に内容を固定する。複数の依頼文を生成している途中で条件が変わったら、同じレビューとして扱わず、どの条件で生成したかを分ける。機密情報や無関係な会話を貼り付けない。
